# 线上检验模板与产品检验工作台实施计划

日期：2026-07-24

## 实施原则

- 严格采用测试驱动开发：每项领域行为先写失败测试，再实现最小代码。
- 不覆盖当前工作区中与本功能无关的未提交修改。
- 客户端兼容后端模板字段尚未上线的情况：显示明确错误，不生成假表格。

## 任务 1：模板与工作台领域模型

新增 `miniprogram/domain/inspection-workbench.ts` 和对应测试，覆盖：

- 模板创建工作台行并保持线上顺序。
- 已有草稿优先恢复测量值、判定、备注和图片。
- 缺少照片标记时，外观和包装默认需要照片。
- 无草稿、无模板时报明确错误。
- 多批次添加照片不设置总数上限。

## 任务 2：OCR 匹配和未匹配区域

先扩展测试，再实现：

- OCR 行保留后端 `row_key` 和 `group_title`。
- 优先按 `row_key` 回填。
- 其次按目标分组和项目名称回填。
- 只允许回填尺寸与安全性能。
- 外观、包装、照片和人工备注不被覆盖。
- 未匹配内容进入待核对列表。

## 任务 3：草稿序列化与图片上传服务

先添加服务测试，再实现：

- 工作台行序列化为现有 `inspection_records`。
- 保存模板 ID、版本和未匹配内容。
- 只保存已上传的图片 URL。
- 新增或复用 multipart 行级图片上传方法。
- 保存使用 `matched_only`。

## 任务 4：产品检验工作台页面

先添加 UI 契约测试，再实现：

- 新增工作台页面、路由、样式和导航栏。
- 任务详情和模板加载状态。
- 横向表格及分组显示。
- 测量值、判定和备注编辑。
- 外观、包装多图选择、上传、预览、删除和重试。
- 质检单拍照/相册识别、进度、结果合并和待核对区域。
- 保存草稿及错误提示。

## 任务 5：待检产品入口

先更新入口测试，再实现：

- 点击产品跳转工作台并携带任务、产品 ID。
- 文案从“选择并拍照”调整为“进入检验”。
- 不再把待检产品强制切换到普通识别首页。

## 任务 6：验证与回归

- 运行新增领域测试。
- 运行服务测试。
- 运行 UI 契约测试。
- 运行完整 `npm test`。
- 运行 `npm run typecheck`。
- 检查 git diff，确保不覆盖用户现有修改。
