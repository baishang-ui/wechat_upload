# 检验报告异步识别队列与字段准确度设计

日期：2026-07-23

## 目标

将微信小程序当前的单图片阻塞式识别流程改为本次运行期间有效的前端单并发识别队列。用户在一张图片识别过程中可以继续拍照或从相册添加图片，队列在小程序保持前台运行时按顺序连续处理。同时由共用后端返回字段级置信度，并结合格式校验在审核表单中标记需要人工核对的字段。

## 已确认决策

- 使用前端单并发队列，不同时调用多个视觉模型请求。
- 队列在当前小程序运行期间有效，不跨小程序退出持久化。
- 第一张识别结束后自动处理下一张，不等待人工审核。
- 用户审核某个结果时，其他队列任务继续处理。
- 采用“模型字段置信度 + 确定性格式校验”。
- 红色：置信度低于 60%，或关键字段为空、格式明显异常。
- 黄色：置信度为 60%（含）至 80%（不含）。
- 正常：置信度不低于 80%。
- 用户修改风险字段后移除风险高亮，但保留原始模型分数直到该条记录完成审核。

## 方案选择

### 采用：前端单并发队列 + 扩展现有识别接口

小程序负责队列生命周期和顺序调度；现有 `/api/miniprogram/quality-inspections/recognize` 接口继续完成单张图片识别，并在兼容原有响应的基础上增加字段置信度。

优势：

- 不需要数据库任务表或后台 Worker。
- 不增加同时调用大模型的服务器压力。
- 可复用现有图片压缩、上传、认证和结果规范化逻辑。
- 与“退出小程序后不恢复队列”的范围一致。

未采用：

- 前端双并发识别：会增加服务器和大模型并发压力，返回顺序不稳定。
- 服务器持久化任务队列：需要任务表、Worker、轮询接口和恢复机制，超出当前范围。

## 运行边界

“后台连续识别”表示：用户在小程序内部切换页面或审核其他结果时，前端队列继续工作。微信将小程序切到操作系统后台、网络中断或进程被回收时，不保证任务继续运行；本设计不实现跨退出恢复。

## 队列模型

每个识别任务包含：

```ts
type RecognitionQueueStatus =
  | 'queued'
  | 'preparing'
  | 'recognizing'
  | 'ready'
  | 'failed'
  | 'skipped'

interface RecognitionQueueItem {
  id: string
  imagePath: string
  createdAt: number
  status: RecognitionQueueStatus
  stage: string
  sourceType: 'standalone' | 'purchase_order'
  taskId: number | null
  itemId: number | null
  taskPrefill: InspectionRecord | null
  result: RecognizeInspectionResult | null
  reviewHints: RecognitionReviewHints | null
  error: string
  skipRequested: boolean
}
```

约束：

- 队列最多保存 10 个尚未完成的任务。
- 相机每次添加一张；相册可在剩余容量内批量添加。
- 任务按 `createdAt` 和加入顺序处理。
- 同一时间最多一个任务处于 `preparing` 或 `recognizing`。
- 采购待检来源在加入队列时固定 `taskId`、`itemId` 和预填数据，避免后续页面选择变化导致串单。
- 已保存任务从队列移除，正式记录由现有历史存储和服务器草稿逻辑管理。

## 队列调度

新增纯函数队列模块负责：

- 创建任务。
- 追加任务并执行容量限制。
- 查找下一个 `queued` 任务。
- 更新任务状态和识别阶段。
- 保存识别结果或错误。
- 重试失败任务，保持原任务 ID，不重复追加。
- 删除等待、失败或待审核任务。
- 标记正在识别的任务为跳过。

页面层维护一个串行 Worker：

1. 检查当前是否已有活动任务。
2. 选择队列中第一个 `queued` 任务。
3. 设置为 `preparing`，执行图片压缩。
4. 设置为 `recognizing`，调用现有识别接口。
5. 成功后保存结果和审核提示，设置为 `ready`。
6. 失败后保存错误，设置为 `failed`。
7. 若任务已请求跳过，丢弃返回结果并设置为 `skipped`。
8. 清除活动标记并立即处理下一个任务。

现有上传封装没有暴露可中止的上传任务，因此“跳过正在识别”是逻辑取消：服务器请求可能继续执行，返回结果会被丢弃，下一项在当前请求结束后开始。等待中的任务可以立即删除。

## 识别页面

现有单任务 `capture / recognizing / review / success` 流程调整为：

- `capture` 作为队列控制台，始终提供拍照和相册添加入口。
- `review` 继续复用现有编辑表单，但绑定当前审核的队列任务 ID。
- 保存成功后移除对应队列任务并写入历史记录。
- 用户可从审核页面返回队列，当前修改保存在队列任务的审核状态中。

队列控制台显示：

- 拍摄检验报告按钮。
- 从相册批量添加按钮。
- 正在识别、等待识别、待审核和识别失败数量。
- 每个任务的图片缩略图、加入时间、来源、状态、进度和风险字段数量。
- 按状态提供“审核结果”“重试”“删除”“跳过”等操作。

状态文案：

- `queued`：等待识别。
- `preparing`：正在处理图片。
- `recognizing`：正在调用视觉大模型。
- `ready`：待人工审核。
- `failed`：识别失败。
- `skipped`：已跳过，随后从可见队列清理。

## 后端响应

原响应继续包含：

```json
{
  "record": {},
  "raw_content": "..."
}
```

新增兼容字段：

```json
{
  "confidence": {
    "fields": {
      "customer": 0.95,
      "supplier": 0.72,
      "trademark": 0.84,
      "order_number": 0.81,
      "model_spec": 0.55,
      "arrival_quantity": 0.74,
      "inspection_date": 0.93,
      "notes": 0.88,
      "reviewer": 0.91,
      "inspector": 0.90
    },
    "items": [
      {
        "name": 0.92,
        "standard": 0.68,
        "specification": 0.57,
        "measurements": [0.98, 0.91, 0.76, 0.52, 0.95, 0.93, 0.88, 0.84, 0.80, 0.79]
      }
    ],
    "sample_judgements": [0.96, 0.87, 0.61, 0.95, 0.90, 0.88, 0.85, 0.83, 0.82, 0.81]
  }
}
```

兼容规则：

- 旧客户端忽略 `confidence`，原有 `record` 和 `raw_content` 不变。
- 后端将分数转换为有限数值并限制到 `0–1`。
- 数组长度不足时由前端按字段异常规则补充风险提示。
- 模型没有返回置信度时，不伪造高置信度；由确定性格式校验决定是否标红，其他未评分字段默认标黄。

## 模型输出与后端校验

视觉模型提示词扩展为同时返回记录和字段置信度。后端解析器负责：

- 接受新的 `{record, confidence}` 模型输出。
- 兼容旧的纯记录模型输出。
- 验证记录字段结构。
- 规范化字段、行项目、十个测量值和十个样本判定的置信度。
- 过滤非数字、NaN 和无限值。
- 将小于 0 的值限制为 0，将大于 1 的值限制为 1。
- 对缺少的分数保留为空，由前端格式规则补充提示。

## 前端审核提示模型

置信度和格式校验结果保留在队列任务的 `reviewHints` 中，不写入最终业务记录结构，避免扩大现有历史和草稿协议。

```ts
type ReviewRiskLevel = 'normal' | 'warning' | 'danger'

interface FieldReviewHint {
  score: number | null
  level: ReviewRiskLevel
  reason: string
  reviewed: boolean
}
```

`RecognitionReviewHints` 使用稳定字段路径索引，例如：

```text
record.customer
record.supplier
record.model
record.inspectionDate
rows.0.item
rows.0.requirement
rows.0.specification
rows.0.measurements.3
sampleJudgements.2
```

这允许表单事件根据字段路径在用户修改时将 `reviewed` 设为 `true`，而不改变原始分数。

## 风险判定规则

### 红色 `danger`

满足任一条件：

- 分数 `< 0.60`。
- 客户、供应商、型号或检验日期为空。
- 检验日期不是可识别的日期格式。
- 到货数量存在内容但无法识别为数量。
- 测量值存在内容但不是合理的数字、范围或允许的判定文本。
- 行项目名称为空。

### 黄色 `warning`

满足任一条件且未命中红色规则：

- `0.60 <= 分数 < 0.80`。
- 模型没有返回该字段分数，且字段未发现确定性格式错误。

### 正常 `normal`

- 分数 `>= 0.80`，并且未命中格式异常规则。

格式异常优先级高于模型分数。例如模型给出 0.92，但关键字段为空，仍标记红色。

## 审核交互

- 红色字段使用浅红背景、红色边框和“重点核对”提示。
- 黄色字段使用浅黄背景、黄色边框和“建议核对”提示。
- 正常字段保持当前表单样式。
- 审核顶部显示红色字段数量和黄色字段数量。
- 用户修改风险字段后，将对应提示标记为已审核并移除风险背景。
- 保留原始分数，不把人工修改伪装为更高模型置信度。
- 保存时若仍有未审核红色字段，显示二次确认弹窗；用户明确确认后允许保存。
- 黄色字段不阻止保存。

## 失败与恢复

- 单个任务失败不会阻塞后续任务。
- 失败任务保留图片、来源上下文和错误信息。
- 重试将同一任务重新设置为 `queued`，不创建重复任务。
- 网络或认证错误按现有错误映射展示。
- 401 继续清除 Session 并返回登录页面；队列为内存状态，因此重新登录后不恢复。
- 删除待审核任务前显示确认，避免误删识别结果。

## 验收标准

1. 第一张图片识别时可以继续添加图片。
2. 队列严格单并发并按加入顺序连续处理。
3. 用户审核结果时其他图片继续识别。
4. 单个失败任务不会阻塞下一项。
5. 采购待检来源不会因后续选择变化发生串单。
6. 红色、黄色和正常阈值按确认标准执行。
7. 确定性格式异常可以覆盖模型高分并标红。
8. 用户修改风险字段后高亮消失，原始分数仍保留在当前队列任务中。
9. 未审核红色字段保存前出现二次确认，但不永久阻止保存。
10. 原有单张识别接口调用方仍能读取 `record` 和 `raw_content`。
11. 小程序测试、类型检查、SCSS 编译和本地真实队列联调通过。
12. 后端聚焦识别测试和 API 联调通过。
13. 不推送远端，保留用户已有未提交修改。

## 非目标

- 不实现跨小程序退出恢复。
- 不实现操作系统后台持续执行保证。
- 不实现多个视觉模型请求并发。
- 不新增数据库任务表或后台 Worker。
- 不将置信度永久写入质检业务记录。
- 不修改现有服务器地址选择策略。
