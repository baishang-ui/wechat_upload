# 小程序临时公开体验模式设计

## 目标

在不删除既有登录能力、也不对生产业务数据开放匿名访问的前提下，让受邀体验者可以直接打开小程序并完成一次真实的检验报告识别体验。

本次体验模式需同时满足：

1. 小程序启动后直接进入首页，不显示登录页，也不因缺少会话跳转到登录页。
2. 小程序请求恢复到线上服务地址 `https://example.invalid`，而不是本机 `http://localhost:7875`。
3. 线上服务实际提供当前小程序使用的识别接口，体验者可上传图片并得到识别结果；不能仅恢复一个可打开但接口 404 的地址。
4. 登录相关页面、服务与正常鉴权接口完整保留。关闭开关即可恢复登录流程。
5. 匿名体验不得读取、修改或删除真实采购任务、真实检验记录或其他用户数据。

## 已确认方案

采用**前端显式体验开关 + 后端最小权限演示身份**方案。

不采用以下方案：

- 删除登录页面或移除后端会话体系：后续恢复成本高，并会破坏正式业务流程。
- 将全部 `/api/miniprogram/*` 接口改为匿名：会暴露采购任务、历史记录及删除能力，风险不可接受。
- 仅把前端地址切回线上：已验证 `https://example.invalid/openapi.json` 可访问，但截至 **2026 年 7 月 24 日**，该实例未暴露 `/api/miniprogram/*` 路由；这样会导致真实识别请求失败。

## 前端设计

### 配置边界

在 `miniprogram/config/server.ts` 中集中维护：

```ts
export const SERVER_BASE_URL = 'https://example.invalid'
export const DEMO_MODE = true
```

`DEMO_MODE` 必须是显式常量，不从 URL、缓存或用户输入中推断，避免体验开关在正式环境意外打开。

### 进入与会话行为

`miniprogram/pages/index/index.ts` 的启动阶段：

- 当 `DEMO_MODE === true` 时，不调用 `getCurrentUser()`，直接加载首页。
- 当 `DEMO_MODE === false` 时，保持现有逻辑：调用 `getCurrentUser()`；若收到 401，则跳转 `/pages/login/login`。
- 历史同步的 `onUnauthorized` 回调在体验模式下不再跳转登录，而是保留本地记录并显示“体验服务暂不可用，请稍后重试”；正式模式维持跳转登录。

登录页仍保留在 `pages/login/login`，但不应成为体验模式的默认入口；页面顺序可调整为首页优先，或保持注册顺序但通过体验模式启动逻辑确保不会跳转登录。具体实现选择以最小改动和测试可覆盖性为准。

### 可体验范围

公开体验只保留“拍照/选图 → 识别 → 本地校对 → 本地历史记录”的闭环。

在体验模式下，前端不得主动调用会触碰业务数据的接口，包括：

- 采购任务列表、采购任务详情；
- 将草稿写入真实采购任务；
- 远程历史列表、远程删除；
- 以真实采购任务为目标的检验日期回写。

历史页继续显示本地存储记录。若当前实现会自动触发远程同步，体验模式应跳过该同步，并将记录保持为本地状态，避免匿名写入服务端。

### 错误呈现

- 识别接口返回 401/403 时，体验模式不跳登录；提示体验服务不可用。
- 识别接口返回 404 时，提示线上体验服务尚未部署，而不是误报为图片或网络问题。
- 其余网络错误沿用现有错误信息，但不得把会话或服务端内部细节展示给用户。

## 后端设计

### 开关与演示身份

在后端增加环境变量：

```text
MINIPROGRAM_DEMO_MODE=false
```

默认必须为 `false`。仅在专门部署的公开体验实例设置为 `true`。

当开关开启且请求访问 `POST /api/miniprogram/quality-inspections/recognize` 时：

- 不要求浏览器会话 Cookie；
- 服务端构造一个固定的、不可登录的演示 `SessionUser`，仅具备调用识别所需的最小权限；
- 识别日志明确记录其为 demo 请求，但不记录原始图片内容或敏感识别文本；
- 接口保持现有文件大小、格式校验、超时和错误响应行为。

当开关关闭时，识别接口继续要求正式会话及 `procurement` 权限，行为与当前生产逻辑一致。

### 明确不开放的接口

体验模式**只**对识别上传接口放开匿名演示访问；以下接口继续会话鉴权，且不为 demo 身份扩权：

- `/api/miniprogram/auth/me`、`/auth/logout` 以外的登录体系保持原状；
- 采购任务查询、详情、草稿保存与日期更新；
- 检验记录列表、创建、编辑、删除与远端同步；
- 其他任何非识别接口。

如果后端当前的路由结构尚未包含这些业务接口，也不得因本次需求临时扩张匿名路由范围。

### 线上部署事实核验

当前线上 `7876` 的 OpenAPI 未包含小程序路由，说明该端口运行的代码或进程不是当前本地仓库的已注册版本。部署前必须在服务器执行：

1. 确认监听 `7876` 的进程、systemd 服务名、工作目录和加载的 `.env` 文件。
2. 确认该进程对应的代码已注册 `routes.miniprogram.router`。
3. 将后端变更部署到该实际运行实例，并仅为体验环境设置 `MINIPROGRAM_DEMO_MODE=true`。
4. 重启后验证 `/openapi.json` 含有 `/api/miniprogram/quality-inspections/recognize`。
5. 使用无 Cookie 的图片上传请求验证识别可用；同时验证任务、历史等受限接口仍返回 401/403。

不能假设 `/opt/smart_sales_system`、`smart_sales_system.service` 或默认 `7875` 正是公开 `7876` 进程；`deploy_one_click.sh` 仅能在上述运行事实确认后使用。

## 测试策略

### 小程序

先测试后实现，至少覆盖：

1. 体验模式启动时不会调用 `getCurrentUser()`，也不会重定向到登录页。
2. 正式模式仍会检查会话，并在 401 时跳转登录。
3. 体验模式下同步遭遇 401 时不会跳转登录，记录保持本地可查看。
4. 线上基地址为 `https://example.invalid`。
5. 体验模式不触发任务、远端历史、远端删除或任务日期回写请求。

### 后端

先测试后实现，至少覆盖：

1. `MINIPROGRAM_DEMO_MODE=false` 时无会话的识别请求仍被拒绝。
2. `MINIPROGRAM_DEMO_MODE=true` 时无会话的合法图片可进入识别服务。
3. 演示请求不能绕过非识别路由的鉴权。
4. 图片大小、格式与模型异常仍分别返回既有的 413、400、502。

## 验收标准

1. 新安装或无会话的小程序可直接到达首页，不出现登录界面。
2. 小程序实际请求线上 `https://example.invalid`。
3. 线上 OpenAPI 包含小程序识别路由，无 Cookie 上传测试返回成功结果或可预期的图片校验错误，而非 404/401。
4. 体验者能完成识别、校对与本地历史保存；正式登录代码未删除。
5. 匿名请求不能读取、改写或删除真实采购和检验数据。
6. 关闭两个演示开关后，客户端与服务端恢复现有登录鉴权流程。
7. 每个行为变更均经过失败测试、通过测试、类型检查和差异检查；提交只包含本任务文件。

## 退出与回滚

体验结束后：

1. 将小程序 `DEMO_MODE` 设为 `false` 并重新上传版本；
2. 将部署环境 `MINIPROGRAM_DEMO_MODE` 设为 `false` 并重启服务；
3. 保留登录代码与服务端会话检查，无需数据迁移或删除演示用户；
4. 若线上接口异常，先将客户端基地址临时回退到稳定服务或关闭体验开关，禁止通过扩大匿名权限作为应急修复。
