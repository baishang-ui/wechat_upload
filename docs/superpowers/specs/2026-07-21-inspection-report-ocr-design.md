# 检验报告 OCR 小程序界面设计

## 目标

在现有微信小程序中构建一套完整的检验报告采集与确认界面。用户一次拍摄或选择一张检验报告图片，小程序展示识别过程，随后以可编辑表格显示 OCR 结果；用户修正并确认后，将结构化检验记录提交给业务服务器。

本轮实现小程序界面、页面状态和真实视觉模型 OCR。根据实施阶段的用户确认，原型直接调用模型网关；最终检验记录的持久化服务器仍未提供。

## 已确认范围

- 一张图片对应一份检验记录。
- 图片来源包括相机拍摄和相册选择。
- OCR 结果中的所有业务字段均可编辑。
- 支持以下六类检验报告：钢丝刷、拉绒片、树脂砂轮、百叶轮、网格砂、金刚石锯片。
- 产品类型由 OCR 自动识别，并允许用户手动修正。
- 检验表格最多包含 10 组测量值。
- 小程序同时显示模型返回的原始 JSON 和归一化后的可编辑表格。
- 用户确认的是结构化 JSON，而不是 OCR 文本截图。
- 模型访问令牌不写入小程序代码、配置或版本库；服务当前未强制认证，可选令牌只从本地存储读取。

## 样例报告结构

样例位于 `$HOME/Downloads/检验报告PDF`。六种产品报告均为 A4 页面，主体表格横向排版，PDF 页面内容带 90 度旋转。每份 PDF 包含三张独立检验记录页面。

报告包含以下共同区域：

- 基本信息：客户、供应商、商标、订单编号、型号/规格、到货数量、检验时间。
- 检验内容：检验项目、标准要求、规格、测量数据 1 至 10。
- 结果信息：OK/NG 判定、描述或备注、审核人、检验员。
- 产品差异：六类产品的检验项目名称和行数不同，因此界面根据产品模板动态生成检验行。

## 方案选择

生产方案仍推荐“微信小程序 + 业务后端代理 + 视觉大模型”的三层结构。当前原型按用户要求直接调用视觉模型接口。

- 推荐方案：小程序只访问 HTTPS 业务接口，业务后端保存模型密钥、规范图片方向、调用视觉模型并校验返回 JSON。该方案安全且便于统一处理 OCR 失败和数据持久化。
- 备选方案：微信云函数代理模型调用。该方案需要额外启用和维护微信云开发环境，当前项目尚未配置。
- 当前原型：小程序直接调用 `https://example.invalid/api/llm/v1/chat/completions`，使用 base64 `image_url` 发送压缩图片。该 HTTP 地址只适合关闭域名校验的开发者工具调试，不满足正式小程序的 HTTPS 与域名白名单要求。

## 页面与状态

首版使用单页状态流，减少页面跳转并保留当前图片和编辑内容。

### 采集状态

- 顶部显示“检验报告识别”和简短操作说明。
- 主操作为“拍摄检验报告”，次操作为“从相册选择”。
- 显示拍摄提示：完整包含四角、避免反光、表格文字清晰。
- 每次只接受一张图片。

### 识别状态

- 显示所选图片缩略图和“正在识别检验报告”状态。
- 使用明确的分步提示表示“读取图片”和“调用视觉大模型”。
- 提供取消识别或重新选择入口。
- 模型使用 `qwen35`，返回 OpenAI 兼容的 `chat.completion` JSON。

### 确认状态

- 顶部显示原图缩略图，可点击预览大图或重新拍摄。
- 在可编辑结果之前显示 API 原始 JSON。
- 产品类型使用选择器显示六类模板，默认采用 OCR 报告标题推断的类型。
- 基本信息以可编辑表单展示。
- 检验内容使用横向滚动表格展示：检验项目、标准要求、规格、测量值 1 至 10。
- 单元格使用输入框编辑，表格底部按样本 1 至 10 分别提供 OK/NG 判定控件。
- 备注、审核人和检验员在表格下方编辑。
- 底部固定主按钮为“确认识别结果”，次操作为“重新识别”。

### 提交状态

- 当前模型接口没有检验记录保存能力，因此确认操作只验证必填字段并生成本地结果编号。
- 提交期间禁用重复操作。
- 成功后显示模拟记录编号，并提供“继续识别下一张”操作。
- 失败时保留全部编辑内容，允许重试。

## 数据模型

前端使用统一结构承载六种产品模板：

```ts
type ProductType =
  | 'steel_brush'
  | 'velcro_disc'
  | 'resin_wheel'
  | 'flap_disc'
  | 'mesh_abrasive'
  | 'diamond_blade'

interface InspectionRow {
  id: string
  item: string
  requirement: string
  specification: string
  measurements: string[]
  lowConfidenceFields: string[]
}

interface InspectionRecord {
  productType: ProductType
  customer: string
  supplier: string
  trademark: string
  orderNumber: string
  model: string
  arrivalQuantity: string
  inspectionDate: string
  rows: InspectionRow[]
  sampleJudgements: Array<'OK' | 'NG' | ''>
  notes: string
  reviewer: string
  inspector: string
}
```

`measurements` 和 `sampleJudgements` 始终规范为长度 10 的数组，空白位置保留空字符串。页面更新时只替换对应字段或数组项，避免编辑一个单元格时覆盖整份记录。

## 当前 API 边界

小程序通过 `wx.request` 调用：

- `POST https://example.invalid/api/llm/v1/chat/completions`：发送 `qwen35` 多模态消息，图片使用 `data:image/...;base64,...`。
- 服务层保留模型原始文本，解析 JSON 后把 snake_case 字段和检验行归一化为 `InspectionRecord`。
- 若模型把“判定”识别为普通检验行，归一化逻辑会把该行移到 `sampleJudgements`。

后续仍需业务服务器提供检验记录保存接口，例如 `POST /api/inspection-records`，接收用户编辑后的 `InspectionRecord` 并返回永久记录编号。

## 错误处理

- 用户取消拍照或相册选择时保持当前状态，不显示错误。
- 图片读取失败时提示重新选择。
- OCR 超时或返回格式错误时显示可重试错误页，并保留原图。
- 必填字段为空时阻止提交，并定位到缺失区域。
- 提交失败时保留编辑结果，不自动返回采集状态。
- 重复点击识别或提交按钮时只执行一次请求。

## 测试与验证

- 为数据模型辅助函数编写单元测试，覆盖 10 个测量位规范化、单元格更新和必填字段验证。
- 使用 TypeScript 编译检查页面数据与事件参数。
- 在微信开发者工具中手工验证相机/相册选择、真实模型识别、原始 JSON、图片预览、横向表格滚动、输入编辑、OK/NG 切换和结果确认。
- 使用窄屏设备预览确认底部按钮、表格横向滚动和输入焦点不互相遮挡。

## 不在本轮范围

- 真实业务后端、数据库和文件存储。
- 用户登录、权限和历史记录列表。
- 编辑后检验记录的远程持久化接口。
- PDF 文件直接上传。
- 多图合并、批量识别或离线识别。
