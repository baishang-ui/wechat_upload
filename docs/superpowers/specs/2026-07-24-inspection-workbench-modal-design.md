# 待检产品检验弹层与分页交互设计

## 目标

将“待检”产品的检验入口从独立页面导航改为首页中的真实底部弹层，使其与识别记录详情弹层保持统一视觉和关闭交互。同时重组检验内容，避免产品信息、识别、宽表和操作按钮在同一屏堆叠，并通过分页让用户在手机上逐步完成检验。

本次改动必须满足：

1. 点击待检产品后，首页仍在背景，检验工作台以底部抽屉形式出现。
2. 抽屉沿用记录详情的毛玻璃遮罩、圆角面板、拖拽条、关闭方式、滚动主体和底部固定操作区。
3. 所有线上模板行、草稿、识别回填、图片上传及草稿保存能力保留。
4. 检验内容不再以超宽横向表格作为主要编辑方式；移动端编辑项应居中、易点按且不同时展示全部内容。
5. 分页保持服务端检验分组和行排序，不得改变写回草稿的数据结构。
6. 关闭含未保存修改的工作台时，用户必须能选择继续编辑、暂不保存或保存草稿。
7. 登录和 Demo 模式策略不因本次界面改造而改变。

## 已确认的交互方案

采用**首页内真实检验工作台抽屉 + 分组分页 + 项目手风琴卡片**方案。

不采用以下方案：

- 保留路由跳转、仅将独立页面视觉上伪装成弹层：无法满足“真正弹出”的要求，也不能保留首页背景。
- 在抽屉中继续渲染完整宽表：仍会导致横向滚动、小输入框和信息密度过高的问题。
- 一页一个完整检验项目：页面数量过多，分组完成进度不清晰。

## 页面结构

### 容器与打开方式

新增可复用组件 `inspection-workbench-modal`，由首页负责：

- 传入 `taskId` 与 `itemId`；
- 控制显示、关闭动画和关闭后的待检列表刷新；
- 在待检产品被选择时打开弹层，不再调用 `wx.navigateTo`；
- 保留现有独立检验页面文件和路由，避免其他既有直接入口立即失效，但待检列表不再使用该路由。

组件按记录详情弹层的语义结构实现：遮罩、面板、拖拽条、标题区、可滚动正文和固定操作栏。遮罩点击、关闭按钮和下拉关闭使用同一未保存检查逻辑。

### 顶部摘要

抽屉头部固定展示：

- 产品名称、物料编码和任务号；
- 当前页标题与整体页码；
- 当前任务待检状态；
- 关闭按钮。

摘要不展示完整元数据。合同号、客户、供应商、规格和数量放到首个“产品与识别”页，使用居中的两列信息卡展示。

## 分页与内容层级

### 页序

1. **产品与识别页**：产品元数据、模板/草稿来源状态、拍摄或选择质检单、缩略图和识别错误提示。
2. **检验分组页**：按后端模板的 `groupTitle` 和 `display_order` 生成。
3. **未匹配识别结果页**：仅在存在未匹配识别行时创建，提示用户人工确认，不打断常规检验页。

每个分组页最多显示三个检验项目摘要；超过三个项目时在同一分组下继续拆页。页码基于已拆分的实际页，且不可依赖固定模板数量。

### 项目卡片

每一项检验以居中的卡片摘要呈现，显示项目名称、填写状态、是否要求图片和展开入口。同一时刻仅允许展开一个项目，避免一屏显示大量输入控件。

展开卡片按以下顺序显示：

1. 标准与检验方法；
2. 测量值输入：按样本编号使用两列网格布局；
3. OK/NG 输入；
4. 备注；
5. 现场图片缩略图、拍摄/相册入口、上传状态和删除入口。

原有列中的额外标准字段使用只读说明区呈现；它们不得丢失，草稿写回继续使用现有行模型。

### 分页控件

底部固定栏包含：

- 上一页；
- `当前页 / 总页数` 与当前分组名称；
- 下一页；
- 保存草稿主按钮。

首尾页禁用不可用方向。用户也可通过顶部紧凑分组/页码指示器跳转。识别完成后，若命中检验行，自动跳转至第一个有回填结果的页面并展开对应项目。

## 数据与状态

### 工作台状态

组件内部负责加载 `getInspectionItemDetail`，恢复：

- 任务和物料元数据；
- 检验模板与服务端草稿；
- 质检单图片；
- 原始识别内容；
- 未匹配识别行；
- 当前编辑行、当前页和未保存状态。

将现有工作台行转换为分页视图模型的逻辑提取为纯函数。该函数必须保留服务端分组顺序、行顺序和行键，并能在识别或编辑后重新计算各页完成状态。

### 保存与关闭

输入、识别回填、图片新增/删除均将工作台标记为未保存。点击保存草稿调用现有草稿保存接口；成功后清除未保存状态，并更新任务列表。

用户关闭存在未保存修改的工作台时展示三项选择：

- 继续编辑：留在弹层；
- 暂不保存：关闭并丢弃仅本次会话的未保存编辑；
- 保存草稿：保存成功后关闭；失败则保留弹层和错误状态。

## 组件边界与兼容性

- 新建工作台弹层组件以及纯分页辅助模块；不要把复杂工作台逻辑继续堆进首页页面文件。
- 首页只处理打开、关闭、任务列表刷新和任务条目的选中状态。
- 复用现有识别、模板、草稿、照片上传和图片预览服务；不修改接口契约。
- 独立工作台路由保留，但可逐步重用相同的工作台内容/辅助逻辑，以避免双套数据合并和保存逻辑。
- 不修改 Demo 模式、登录流程、记录详情弹层行为或远端权限边界。

## 测试策略

### 纯逻辑

先写失败测试，覆盖：

1. 按分组和每页三项规则生成稳定页序；
2. 空分组、超过三项的分组及未匹配识别页的页码；
3. 根据行填写、图片和识别结果计算项目/页面状态；
4. 识别命中行能够定位到正确分页并展开该行；
5. 写回草稿前的行数据、图片 URL 和识别结果不因分页丢失。

### 页面与组件结构

先写失败测试，覆盖：

1. 待检产品点击打开弹层，不调用独立工作台路由；
2. 弹层包含记录详情一致的遮罩、面板、拖拽条、可滚动正文和底部操作栏；
3. 识别入口仅在产品与识别页；
4. 检验项目使用卡片与可展开输入区，不以完整横向表格渲染；
5. 上一页、下一页、页码和保存操作存在并具备禁用状态；
6. 未保存关闭会显示三选项确认路径。

### 回归验证

实现完成后运行：

```bash
npm test
npm run typecheck
git diff --check
```

并手动在微信开发者工具中验证：打开动画、关闭动画、长分组分页、识别回填跳页、图片上传、保存草稿、关闭未保存提示及任务列表刷新。

## 验收标准

1. 点击待检产品时，在首页上弹出真实检验抽屉，不发生页面导航。
2. 弹层视觉和交互与记录详情弹层一致。
3. 首屏只呈现产品与识别必要信息；完整检验项按分组分页呈现。
4. 用户无需横向拖动宽表即可填写核心数据、备注和图片。
5. 分组、行顺序、草稿恢复、识别回填、图片上传和保存功能正确。
6. 关闭未保存工作台不会静默丢失数据。
7. 登录、Demo 模式和既有记录弹层行为不回归。
