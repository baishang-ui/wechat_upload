# 两路并发检验识别队列设计

## 目标

缩短用户一次选择多张检验报告图片后的**总识别完成时间**。当前页面只在上一张图片的识别请求结束后才启动下一张，多个任务的总耗时近似为每张耗时之和。

本次采用受控并发：同时运行最多两张图片的识别请求。这样在不改变现有单张上传接口和识别结果格式的前提下，提高整体吞吐量，同时控制本地后端与模型接口的压力。

## 已确认方案

- 最大并发数固定为 `2`。
- 任何时刻最多两个队列项处于 `preparing` 或 `recognizing` 状态。
- 添加图片、识别完成、识别失败、跳过或重试后，调度器都会补足可用并发槽位，直到没有等待中的任务或两个槽位都被占用。
- 仍调用现有单张接口 `POST /api/miniprogram/quality-inspections/recognize`；不引入批量上传接口，不改变服务器请求超时和数据保存流程。
- 每张活动卡片拥有独立的进度启动时间和定时器。进度沿用现有的 6 秒“前慢、中后快”曲线：真实请求提前完成时立即变为 `100%`，未完成时最高停在 `92%`。
- 一张任务失败、跳过或取消不能停止其他活动任务，也不能阻止等待任务占用释放的槽位。
- 队列仍可显示最多 10 张卡片；用户现有的打开校对、保存、删除、重试和跳过行为保持不变。

## 调度模型

```text
等待队列 ──> 启动到两个空闲槽位 ──> 单张识别请求
                                       │
             <── 完成 / 失败 / 跳过 ──┘
                 释放一个槽位并立即补位
```

页面层维护活动任务集合，而不是单个 `activeRecognitionQueueId`。调度函数的职责是：计算当前活动数、依次获取等待任务、将其标记为活动、启动对应请求和独立进度更新，直至活动数达到 2 或没有等待任务。

请求结束时仅清理自身的进度资源、更新自身卡片状态，再调用调度函数补位；不会重置或停止其他卡片。

## 代码边界

### `miniprogram/domain/recognition-queue.ts`

- 新增并导出最大并发常量，例如 `MAX_CONCURRENT_RECOGNITIONS = 2`。
- 继续由纯函数管理队列项状态与统计数据。
- 现有 `getTimedRecognitionProgress()` 保持 6 秒分段曲线，不把页面定时器状态写入领域层。

### `miniprogram/pages/index/index.ts`

- 将单一活动任务状态替换为可表示多个活动项的状态或页面外部任务映射。
- 将单一全局进度计时器替换为按队列项 ID 管理的计时器和开始时间。
- 提取“启动单项识别”和“填充空闲槽位”两个职责明确的方法，避免在多个回调中复制调度逻辑。
- `onUnload` / `detached` 等页面退出路径必须清理所有活动进度定时器。

### `tests/recognition-queue.test.ts` 与页面/UI 测试

- 验证并发上限为 2。
- 验证两个任务可同时从等待状态转为活动状态，而第三个任务保持等待。
- 验证任一活动任务完成、失败或跳过后，会启动下一张等待任务。
- 验证每张活动卡片独立推进进度，一个任务的结束不会关闭另一个任务的进度更新。
- 保留既有单张识别、失败、重试和 6 秒非匀速进度的回归覆盖。

## 错误处理与兼容性

- 单个上传或模型调用失败时，仅对应卡片显示失败信息；其他正在运行或等待中的任务继续执行。
- 请求仍使用当前 `120000ms` 上传超时。受控并发只改变并行度，不把超时阈值缩短为更容易失败的数值。
- 本地后端若承受两条并发请求时表现出明确的限流或超时，再在后续迭代中降低并发或引入后端任务调度；本次不默认提升到 3 路并发。
- 识别结果仍按原有结构进入校对与保存流程，购买订单预填信息的合并逻辑不变。

## 验收标准

1. 同时选择三张或更多图片时，最多两张立即进入“准备中 / 识别中”，剩余卡片保持“等待识别”。
2. 任一活动任务结束后，若有等待卡片，下一张立即启动；队列不会退化为串行。
3. 从开始到所有任务完成的总耗时，在后端可并发处理时明显低于原有串行总耗时；理论上大量任务接近单张平均耗时乘以 `ceil(任务数 / 2)`。
4. 同时运行的卡片各自独立显示并推进进度，真实完成立即显示 `100%`。
5. 一个任务失败、跳过、重试或完成不会影响其他活动卡片的状态和进度。
6. 页面离开后不遗留进度定时器。
7. 新增回归测试先失败后通过；`npm test`、`npm run typecheck` 和 `git diff --check` 均通过。
