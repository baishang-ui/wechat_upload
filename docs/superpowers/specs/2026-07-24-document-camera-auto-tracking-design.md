# 手机拍照自动跟踪与透视校正设计

**日期：** 2026-07-24
**范围：** 微信小程序检验报告相机页。相册导入、识别队列和后端 OCR 接口保持不变。

## 背景

现有相机页以约 420ms 的间隔检测预览帧，只能输出轴对齐矩形；连续三帧接近时进入可拍摄状态。手机轻微移动、纸张倾斜、阴影或短暂反光会导致框线抖动、跳变或丢失，并且拍后只能矩形裁切。

## 目标

1. 检测并跟踪检验报告的真实四个角点。
2. 对角点进行动态平滑，兼顾稳定性与跟随速度。
3. 短暂检测失败时保留可信结果，避免 UI 闪烁。
4. 默认自动拍摄，可切换手动拍摄。
5. 稳定后进行一秒倒计时；移动报告立即取消。
6. 拍后优先执行透视拉正，失败时依次降级为矩形裁切和原图。
7. 优化快门为专业相机样式，并显示稳定进度、倒计时和处理状态。
8. 保留“重拍 / 使用照片”确认页。

## 方案选择

采用小程序端实时检测和本地校正：预览帧使用低分辨率纯 TypeScript 图像算法，覆盖 Canvas 绘制四边形；拍照后通过本地 Canvas 网格透视变换输出校正图。该方案无需额外网络请求，也不引入体积较大的 OpenCV/WASM。

## 跟踪模型

### 单帧检测

1. 将相机 RGBA 帧按设备性能限制缩小。
2. 灰度化并计算水平、垂直梯度。
3. 在多个扫描带中寻找高强度边缘点。
4. 对左右边、上下边分别拟合直线。
5. 求四条边交点，得到左上、右上、右下、左下角点。
6. 校验凸性、面积、边长、角度、中心位置和边缘能量。
7. 根据边缘能量、几何完整度和面积生成置信度。
8. 检测失败时兼容原轴对齐候选作为低优先级降级结果。

### 时序平滑

维护跟踪状态而不是直接显示每帧检测结果：

- 静止时使用较强平滑，减少抖动。
- 位移较大时降低平滑权重，让框线及时跟随。
- 根据角点漂移、面积变化和置信度计算稳定进度。
- 最近可信结果在短暂丢失的 600ms 内继续显示，但不会继续累计自动拍摄进度。
- 搜索、跟踪、稳定状态采用不同进入/退出阈值，避免频繁切换。
- 稳定判定使用持续时间，目标约 600ms，而不是固定帧数。

跟踪状态：

```text
searching -> tracking -> stabilizing -> ready -> countdown -> capturing
```

页面兼容现有样式名时，可将 tracking/stabilizing 映射为 aligning。

## 自动拍摄

- 页面默认自动模式。
- 自动和手动可通过分段开关切换。
- 自动模式达到 ready 后启动一秒倒计时。
- 每个检测周期都重新验证角点稳定度和清晰度。
- 位移超限、文档丢失、页面隐藏、模式切换或拍摄开始时立即取消倒计时。
- 自动拍摄设置一次性锁，防止定时器和手动点击重复调用 `takePhoto`。
- 自动模式中仍允许用户提前点击快门。
- 手动模式不启动倒计时，但继续提供四角跟踪和透视校正。

## 视觉设计

### 四角覆盖层

使用透明 Canvas 绘制：

- 四边形外侧半透明遮罩；
- 搜索状态为中性引导框；
- 跟踪中为白色或浅蓝色四边框；
- 稳定后为绿色四边框和角标；
- 短暂丢失时降低透明度，不立即跳回默认框。

### 专业快门

- 快门使用大尺寸圆形触控区。
- 白色内圆、半透明外圈。
- 跟踪到文档后外圈呈现稳定进度。
- ready 和倒计时状态使用绿色外圈。
- 倒计时中央显示 1。
- 按下时提供缩放反馈。
- 拍摄处理中显示旋转加载环并禁止重复触发。
- 快门上方显示“自动 / 手动”分段切换。

## 透视校正

1. 拍摄时冻结最后一组稳定四角坐标。
2. 根据相机预览的 aspect-fill 映射和照片方向，将归一化角点转换为高清照片坐标。
3. 根据上下边、左右边长度估算目标宽高。
4. 将输出最大边限制为 1800px。
5. 使用分块网格将四边形映射到矩形；网格单元采用 Canvas 仿射三角形绘制，避免一次性读取超大像素数组。
6. 输出 JPEG，质量保持 0.92。

降级顺序：

```text
透视拉正 -> 四角包围矩形裁切 -> 原始照片
```

## 错误与降级

- 设备不支持相机帧：保留手动快门，自动模式不可用并给出提示。
- 检测器异常：清除倒计时，继续允许手动拍摄。
- Canvas 透视处理失败：自动尝试矩形裁切。
- 裁切再次失败：使用原图进入确认页。
- 页面隐藏或销毁：停止帧监听和所有计时器。

## 测试策略

### 纯函数

- 倾斜高对比度文档能得到非轴对齐四角。
- 角点顺序、凸性和边界合法。
- 动态平滑减少微小抖动，并能跟随明显移动。
- 短暂丢帧保留显示结果，但不错误进入 ready。
- 基于时间的稳定进度正确。
- 自动倒计时在移动、丢失和切换模式时取消。
- 预览坐标到原图坐标映射正确。
- 透视输出尺寸计算有上限。

### 页面行为

- 默认自动模式并提供切换控件。
- 页面存在四边形 Canvas 覆盖层。
- ready 后启动一秒倒计时。
- 快门可手动点击，且不存在重复拍摄。
- 拍后仍显示确认页面。
- 页面离开时清理监听器和倒计时。

### 回归

- 相机确认结果仍通过首页加入既有识别队列。
- 相册批量添加与并发识别不受影响。

## 验收标准

1. 倾斜报告能显示贴合四角的边框。
2. 轻微手抖时框线视觉稳定，移动报告时仍能快速跟随。
3. 短暂反光或遮挡不会立即让框线跳回默认位置。
4. 默认自动模式；可随时切换手动模式。
5. 稳定约 600ms 后显示一秒倒计时并自动拍摄。
6. 倒计时中移动报告会立即取消。
7. 专业快门显示稳定进度、倒计时和拍摄中状态。
8. 拍后优先得到透视拉正图片；处理失败不会丢失原图。
9. 保留“重拍 / 使用照片”确认。
10. 类型检查和全部相关回归测试通过。

## 视觉修订（2026-07-24，用户确认）

针对真机反馈，取景界面采用“固定取景范围 + 轻量动态跟踪线”的双层表达：

- 屏幕中央增加固定竖向取景框，位置不随检测结果移动，用于明确报告应放置的范围。
- 动态四角检测仍用于稳定判断、自动拍摄和透视校正，但只显示低对比度细线与小角点，不再承担主取景框视觉。
- 取消大面积深色内外遮罩，外部仅保留非常轻的透明蒙层，降低框内外亮度落差。
- 快门按钮容器改为完全透明，移除外层椭圆/光晕背景，仅保留圆形进度环和中心快门。
- 顶栏增加安全区后的额外上边距，并同步下移状态提示，避免贴顶。
- searching 状态不再绘制会被误认为检测结果的默认动态四边形；固定取景框始终提供构图参考。

## 高清原图与追踪简化修订（2026-07-24，用户确认）

真机验证后进一步简化拍摄链路：

- 页面完全隐藏动态四角追踪线，仅保留固定取景框；边缘检测继续在后台用于稳定状态和自动倒计时。
- 拍照结果直接使用 `CameraContext.takePhoto` 返回的高清临时文件，不再经过 Canvas 透视网格、自动裁切、尺寸压缩或 JPEG 二次编码。
- 取消追踪结果对照片几何形状的影响，避免透视拉伸、局部变形和清晰度下降。
- 快门从原生 `button` 改为普通 `view` 点击区域，禁用原生 hover 层，仅保留自定义圆形缩放反馈，彻底去除按压椭圆背景。
- “重拍 / 使用照片”确认流程保持不变。

## 居中 3:4 预览窗口修订（2026-07-24，用户确认）

为提升构图可见性且避免全屏预览带来的干扰，拍摄页仅调整相机预览展示区域：

- 相机预览改为屏幕中央、与屏幕等宽的固定 **3:4 竖向**窗口，高度按 `宽度 × 4 / 3` 计算。
- 固定取景框与相机预览同属该窗口并完全贴合其范围；顶部栏、状态提示、模式切换和快门继续位于窗口外的页面覆盖层。
- 页面其余区域保持深色背景；预览窗口使用轻量圆角、细边框和阴影区分边界，不增加影响观察的重遮罩。
- 该改动仅影响实时预览布局，不影响 `takePhoto({ quality: 'high' })` 的拍摄结果：确认页继续使用相机返回的高清原图，不裁切、不压缩、不做透视拉伸。

## 竖向 3:4 与重拍、顶部安全区修订（2026-07-24，用户反馈）

- 用户所述“四比三”按页面方向明确为横向 3、纵向 4，即预览窗口宽高比为 **3:4**；窗口与屏幕等宽，高度按 `宽度 × 4 / 3` 计算。
- 相机和固定取景框保持常驻挂载，确认照片时只隐藏预览窗口，不再通过 `wx:if` 销毁原生相机组件；点击“重拍”后直接恢复同一相机预览，避免黑屏或无画面。
- 顶部使用系统状态栏高度和胶囊按钮位置计算显式安全占位，不再只依赖可能返回 0 的 `env(safe-area-inset-top)`。
- 顶部关闭按钮和标题使用 `cover-view`，并置于相机原生层之上，确保真机上按钮可以点击。

## 稳定判定放宽与 1 秒倒计时修订（2026-07-24，用户确认）

- 轻微手持晃动允许的四角最大漂移由归一化 `0.035` 放宽到 `0.055`。
- 相邻检测结果允许的面积变化由 `12%` 放宽到 `20%`，减少轻微远近移动导致稳定进度反复清零。
- 连续稳定确认时间由 `900ms` 缩短到 `600ms`。
- 达到 ready 状态后的自动拍摄倒计时由 `3 秒` 缩短为 `1 秒`；报告明显移动、识别丢失或切换模式时仍立即取消自动拍摄。
- 快门进度环同步按 1 秒时长计算，避免倒计时结束后进度显示不一致。


## 顶部关闭按钮与拍摄模式滑块修订（2026-07-24，用户确认）

### 顶部关闭按钮

- 保留“关闭”文字和现有点击行为，不改为难以识别的纯图标。
- 按钮使用固定宽高的半透明磨砂胶囊，采用 Flex 双轴居中，不再依赖 `line-height` 对 `cover-view` 文字进行垂直定位。
- 使用轻量边框、柔和阴影和较低透明度背景，使其在明暗相机画面上均保持可见，同时避免视觉过重。
- 增加独立按压态：按下时轻微缩小并降低背景亮度，不使用原生按钮背景或椭圆形 hover 层。
- 顶栏左右占位保持等宽，保证标题继续严格居中。

### 自动 / 手动拍摄切换

- 分段控件内部增加一个独立的绝对定位滑块，两个文字选项保持在滑块上层。
- 自动模式下滑块位于左侧；手动模式下通过 `translate3d` 平移到右侧，避免直接切换选项背景造成跳变。
- 位移动画复用首页底栏参数：`0.34s cubic-bezier(.22, .8, .28, 1)`，并设置 `will-change: transform`。
- 选项激活态只切换文字颜色，不再自行绘制白色背景和阴影。
- 触摸开始时滑块轻微放大，触摸结束或取消时恢复，反馈方式与首页底栏的移动指示块一致。
- 模式切换业务逻辑、自动拍摄取消逻辑和无实时帧能力时的降级逻辑保持不变。

### 验收补充

1. 真机中“关闭”文字在胶囊内水平、垂直居中，按钮可正常点击。
2. 按压关闭按钮时只有胶囊自身轻微缩放，不出现额外椭圆背景。
3. 自动与手动模式切换时，白色滑块以与首页底栏一致的位移时长和缓动移动。
4. 快速点击或触摸取消后，滑块不会停留在放大状态。
5. 两种模式下文字颜色清晰，滑块与文字层级正确。

- 相邻检测结果面积变化容差由 `20%` 放宽为 `28%`。
- 连续稳定确认时间保持 `600ms`，自动拍摄倒计时保持 `1s`。

## 横屏照片自动转正（2026-07-24，用户选择 A）

- `takePhoto({ quality: 'high' })` 返回照片后，先通过 `wx.getImageInfo` 读取原始像素尺寸和 EXIF 方向。
- EXIF 为 `up` 时直接使用相机高清原图，不经过 Canvas，也不产生二次编码。
- EXIF 表示 `right`、`left`、`down` 或镜像方向时，按对应矩阵在隐藏 Canvas 上将像素物理转正；90 度方向交换输出宽高，其他方向保持原始宽高。
- 转正输出保持原始像素尺寸，不裁切、不缩放、不做透视处理，JPEG 输出质量设为 `1`。
- 转正后的临时文件同时用于确认页和后续质检单识别，避免只修正预览但识别端仍收到横向像素。
- 如果方向读取或 Canvas 输出失败，保留相机高清原图并在确认页提示方向校正未完成，不能因转正失败丢失已拍照片。

## 0.6 秒自动拍摄、横图回退转正与关闭文字定位修订（2026-07-24，用户确认 A）

- ready 后的自动拍摄等待由 `1000ms` 缩短为 `600ms`，快门进度环按 `elapsed / 6` 同步递减；稳定确认时间仍保持 `600ms`。
- 拍摄页面启动设备方向监听，并在调用 `takePhoto` 前冻结拍照瞬间的 `gamma` 值，避免拍后转动手机影响方向判断；页面隐藏或销毁时解绑并停止监听。
- EXIF 不是 `up` 时继续优先使用原有八方向矩阵；EXIF 为 `up` 且原始像素仍为横向时，根据拍照瞬间设备方向选择顺时针或逆时针旋转 90°。
- 设备方向不足以判断左右横持时默认顺时针转正，确保 `up` 横图不再直接绕过校正；原始像素已经是竖向时仍保留高清原图，不进行二次编码。
- 顶部关闭按钮改为外层磨砂胶囊与内层绝对定位文字两层结构；文字通过 `top/left: 50%` 和 `translate(-50%, -50%)` 居中，不再依赖 `cover-view` 的 Flex 字体基线。

## 真机方向 Canvas 与确认按钮修订（2026-07-24，用户确认）

- 真机方向校正失败的直接风险来自隐藏 Canvas 的 CSS 尺寸被固定为 `1px × 1px`；WXML 的图片尺寸绑定无法保证旧版 Canvas 绘图区同步扩展。
- 隐藏 Canvas 改为通过内联 `style` 使用 `orientationCanvasWidth/Height` 设置真实绘图区尺寸，并移除 SCSS 中的 `1px` 宽高限制。
- 更新 Canvas 尺寸后等待 `wx.nextTick`，确认原生 Canvas 节点完成布局，再创建绘图上下文和导出转正照片，避免仍在旧尺寸上绘制。
- 确认页“重拍 / 使用照片”从原生 `button` 改为自定义 `view` 控件，移除原生字体基线、内边距和伪元素差异。
- 两个按钮的文字使用独立绝对定位层，通过 `top/left: 50%` 与 `translate(-50%, -50%)` 严格居中，并增加仅作用于控件本身的轻量缩放按压反馈。

## 真机方向校正可观测性与 Canvas 2D 修订（2026-07-24，用户反馈）

- 拍照成功后立即使用相机原图进入确认页，先明确显示“正在读取照片方向并校正…”，不再等待异步方向处理完成后才显示确认页面。
- 旧版 `wx.createCanvasContext` 隐藏画布流程迁移为 `canvas type="2d"` 节点：通过选择器取得 Canvas 实例、设置真实像素宽高、使用 `canvas.createImage()` 加载原图并按方向矩阵绘制。
- 导出使用 `wx.canvasToTempFilePath({ canvas })`，随后重新读取导出图片尺寸，验证目标横竖方向确实生效；方向不一致按失败处理并保留原图。
- 方向读取、Canvas 加载、绘制或导出失败时不得静默：控制台记录原始方向、尺寸、设备方向和错误；确认页显示失败说明，并弹出“照片转正失败，已保留原图”。
- 确认页图片、渐变、说明文字和操作按钮分别固定为 `z-index: 1/2/3/4`，保证真机原生渲染层级下处理提示仍可见。
- 方向处理完成前禁止重拍或提交照片，避免异步校正结果覆盖重拍页面，或将仍未处理完成的原图提前送入识别队列。

## 横持方向优先于误导性图片宽高（2026-07-24，用户真机反馈）

- 真机可能返回 `orientation = up`，同时文件宽高仍保持竖向，但实际像素内容已经随横持手机侧转；仅凭 `width > height` 会错误显示“照片方向正常”。
- 拍照瞬间同时冻结设备运动 `gamma` 和系统 `deviceOrientation`；`gamma` 可判断左横持/右横持，系统横屏状态在 `gamma` 不明确时提供顺时针回退。
- 当拍照瞬间已明确为横持时，即使文件元数据宽高仍是竖向，也必须执行 90° 像素旋转并交换输出宽高，不允许再因竖向尺寸绕过校正。
- 只有 EXIF 为 `up`、设备未检测到横持且原始像素也是竖向时，才显示“照片方向正常”并保留原图。
