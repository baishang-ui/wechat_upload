# 微信小程序登录页与待检页面视觉统一设计

日期：2026-07-23

## 目标

让登录页和新增的“采购待检任务”页面与现有“拍照识别”“识别记录”页面使用同一套视觉语言，同时保持现有登录、任务查询、质检和页面切换逻辑不变。

## 视觉基准

以当前内部“拍照识别”页面为基准：

- 页面背景：浅灰蓝 `#f3f6f8`
- 内容卡片：白色背景、浅色边框、`24rpx` 圆角、轻量蓝灰阴影
- 主色：蓝色 `#2f6bff`
- 主文字：深蓝灰 `#17233d`
- 次级文字：灰蓝 `#77839a`
- 主按钮：蓝色背景、白色文字、明确的按压反馈
- 内容进入使用轻量上移动效，避免增加复杂动画

## 范围

### 登录页面

调整登录页面的 WXML 与 SCSS：

1. 移除当前独立的渐变背景，改用内部页面浅灰背景。
2. 登录卡片与内部 Hero Card 使用相同的边框、圆角和阴影。
3. 标题区域使用内部页面的层级：蓝色英文眉题、主标题、灰色说明文字。
4. 用户名和密码输入框统一为内部表单控件风格。
5. 登录按钮统一为内部蓝色主按钮样式。
6. 登录错误显示为浅红色提示条，并保持文字清晰可读。
7. 保留提交中、禁用、回车登录、错误处理和成功跳转行为。
8. 适配安全区和小屏幕高度，避免键盘弹出后主要控件不可操作。

### 采购待检任务页面

调整 `index` 页面中任务区域的结构样式，不改变任务数据和事件处理：

1. 搜索工具栏继续使用卡片容器，并与其他功能卡片统一间距和圆角。
2. 搜索输入框、搜索按钮与内部表单和主按钮统一。
3. “待检 / 已完成 / 全部”筛选项使用统一的胶囊状态样式。
4. 任务卡片统一边框、阴影、标题层级、信息间距和按压反馈。
5. 客户、供应商、采购合同和产品信息建立稳定的主次层级。
6. 待检和已完成状态使用语义化蓝色、绿色标签。
7. 当前选中的任务或产品使用低对比蓝色背景和边框高亮，不改变点击区域。
8. 加载、空数据、错误、重试和列表到底状态与现有内部空状态一致。
9. 保持底部浮动导航、分页加载、任务展开及质检入口行为不变。

## 公共样式策略

新增一个轻量 SCSS 设计变量文件，供登录页和内部页面导入，至少包含：

- 页面背景色
- 主色、主文字色、次级文字色
- 卡片边框色、阴影和圆角
- 表单背景与边框色
- 成功色、错误色及其浅色背景

现有组件选择器保持不变，优先通过变量替换重复的硬编码值，避免进行与本次目标无关的大范围重构。

## 交互与数据边界

本次只调整视觉表现，不修改：

- 登录 API、Session Cookie 和认证流程
- 服务器地址配置方式
- 采购待检任务 API 和查询参数
- 任务分页、筛选、搜索和选择逻辑
- 质检识别、草稿保存及历史同步逻辑
- 小程序页面路由和底部功能入口

## 验收标准

1. 登录页、拍照识别、采购待检任务和识别记录在背景、卡片、按钮、文字层级上明显属于同一设计系统。
2. 登录页不再呈现与内部页面不同的渐变和超大卡片风格。
3. 待检工具栏、筛选项、任务卡片和状态页的间距、圆角、阴影统一。
4. 小屏幕和键盘弹出场景下，登录按钮仍可操作。
5. 登录、筛选、搜索、分页、打开任务、进入质检等原有行为不发生变化。
6. 小程序自动化测试、TypeScript 类型检查和 `git diff --check` 全部通过。
7. 在微信开发者工具中分别检查登录页、待检空状态、待检列表和任务选中状态。

## 非目标

- 不重新设计拍照识别或识别记录的业务结构。
- 不新增图片、图标库或第三方 UI 框架。
- 不调整后端、数据库或线上部署配置。
- 不为真机和开发者工具引入不同的视觉版本。
