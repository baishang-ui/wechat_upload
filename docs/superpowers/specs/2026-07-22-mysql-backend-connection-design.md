# MySQL 服务端连接设计

## 目标

为当前检验报告 OCR 微信小程序增加安全的远程 MySQL 连接能力。小程序不直接连接数据库，而是通过新增的 Node.js HTTP 服务访问数据库。本轮完成服务端配置、连接池、健康检查接口和真实连接验证，不迁移现有本地历史记录，也不设计业务数据表。

目标数据库位于局域网 MySQL 服务。实际主机、端口、用户名、密码和数据库名由服务端环境变量提供；任何真实密码都不得进入小程序代码、测试、文档或 Git 历史。

## 架构选择

采用独立 Node.js + TypeScript API 服务：

```text
微信小程序 / 调试客户端
          |
          | HTTP GET /api/health/mysql
          v
Node.js API 服务
          |
          | MySQL TCP + 连接池
          v
远程 MySQL 数据库
```

不采用小程序直连 MySQL，因为小程序不提供标准 MySQL TCP 客户端能力，而且客户端包可被提取，无法安全保存数据库凭据。不采用云函数作为本轮方案，因为目标是局域网地址，云端通常无法直接访问该地址。

## 服务端模块

新增 `server/` 目录，模块职责如下：

- `config.ts`：读取并校验环境变量，转换端口等类型；缺少必填值时快速失败。
- `database.ts`：创建和复用 `mysql2/promise` 连接池，提供数据库探活方法和关闭方法。
- `app.ts`：创建 HTTP 应用并注册路由，不直接启动监听，便于自动化测试。
- `index.ts`：加载环境配置、启动服务、处理退出信号并关闭连接池。

服务默认监听 `0.0.0.0`，端口由 `SERVER_PORT` 控制，默认值为 `3000`。绑定全部本地网卡仅用于允许同一局域网中的微信开发者工具或真机访问；生产环境仍应通过受控网络和 HTTPS 反向代理暴露 API。

## 环境变量与凭据安全

服务端使用以下变量：

```text
MYSQL_HOST
MYSQL_PORT
MYSQL_USER
MYSQL_PASSWORD
MYSQL_DATABASE
SERVER_HOST
SERVER_PORT
```

- 根目录 `.env` 保存本地真实参数，并加入 `.gitignore`。
- `.env.example` 只保存变量名和无敏感占位值。
- 小程序源码不包含数据库地址、账号或密码。
- 日志和 HTTP 响应不输出密码、完整连接字符串或底层堆栈。
- 健康检查返回数据库名是为了确认选库正确，但不返回用户名。

## 数据库连接

使用 `mysql2/promise` 连接池，而不是每次请求创建新连接。初始配置保持精简：

- 有限连接数，避免开发环境耗尽数据库连接。
- 开启等待可用连接。
- 设置连接和查询超时，避免接口无限挂起。
- 使用环境变量指定字符集兼容的目标数据库。

探活查询执行参数固定的只读 SQL：

```sql
SELECT 1 AS ok, DATABASE() AS database_name, NOW() AS server_time
```

成功必须同时满足：完成 MySQL 身份认证、成功选中配置数据库、查询返回 `ok = 1`，且 `DATABASE()` 与配置数据库一致。

## HTTP 接口

新增：

```text
GET /api/health/mysql
```

成功返回 HTTP 200：

```json
{
  "ok": true,
  "database": "configured_database",
  "serverTime": "2026-07-22T00:00:00.000Z"
}
```

失败返回 HTTP 503：

```json
{
  "ok": false,
  "error": "MYSQL_UNAVAILABLE"
}
```

服务器时间统一序列化为 ISO 8601 字符串。错误响应使用稳定错误码，不向客户端暴露数据库驱动错误详情；详细原因只在服务端以脱敏方式记录。

另提供普通进程探活接口 `GET /api/health`，它只确认 Node.js 服务正常运行，不访问数据库，便于区分 HTTP 服务故障和数据库故障。

## 小程序边界

本轮不在现有页面增加可见按钮，也不把健康检查作为启动前置条件。数据库连接能力首先作为后端基础设施落地，避免数据库临时故障阻塞 OCR 和本地历史功能。后续业务同步接口应继续通过该服务端访问连接池。

README 将补充服务端安装、配置、启动和测试命令，以及小程序只能调用 HTTP API、不能直连 MySQL 的说明。

## 错误处理

- 环境变量缺失或端口非法：服务启动前失败，并输出缺失变量名，不输出变量值。
- TCP 不可达、认证失败、数据库不存在或查询超时：数据库健康接口返回 503。
- 启动期间发生监听错误：进程以非零状态退出。
- 收到 `SIGINT` 或 `SIGTERM`：停止 HTTP 服务并关闭数据库连接池。

## 测试与验证

自动化测试覆盖：

- 环境变量完整时生成正确的类型化配置。
- 必填变量缺失和非法端口时拒绝启动。
- 普通健康接口返回 200。
- 数据库探活成功时返回 200 和规范化结果。
- 数据库探活失败时返回 503，且响应不泄露底层错误或凭据。

真实连接验证使用本地 `.env` 中的参数，依次确认：

1. 目标主机的 3306 TCP 端口可达。
2. MySQL 用户身份认证成功。
3. 目标数据库可被选择。
4. 探活 SQL 返回预期结果。
5. HTTP 数据库健康接口返回 200。

截至 2026 年 7 月 22 日，已完成第 1 项 TCP 测试，目标端口可达；其余项目在服务实现后执行。

## 非本轮范围

- 创建、修改或删除 MySQL 表。
- 将现有本地历史记录上传或同步到数据库。
- 用户登录、权限模型和多租户隔离。
- 从公网直接暴露 MySQL 或 Node.js 开发端口。
- 生产 HTTPS、域名备案、微信公众平台合法域名配置和部署自动化。
