# 悬浮导航与本地识别记录设计

## 目标

在现有检验报告 OCR 小程序中增加底部悬浮导航，并提供可持久化的本地识别记录。用户可在“识别”和“记录”两个工作区之间切换，打开历史记录后继续编辑原始识别表格，再次确认时更新同一条记录。

本轮只使用微信本地文件与本地存储，不新增服务器同步接口。

## 导航结构

首页继续使用单页组件，新增 `activeTab` 状态：

- `scan`：拍照、识别、查看 API 原始 JSON、编辑表格和确认结果。
- `history`：浏览、打开和删除已确认的识别记录。

底部导航采用固定悬浮栏，左右各一个等宽入口。导航栏距离屏幕左右边缘 28rpx，底部包含 `env(safe-area-inset-bottom)`，页面内容增加对应底部留白，避免表格按钮和列表内容被遮挡。

识别请求运行期间允许切换到记录栏。请求完成后只更新识别栏状态，不强制打断用户当前浏览；用户再次进入识别栏时可看到识别结果。

## 识别栏优化

- 保留拍照和相册选择入口，一次处理一张图片。
- 保留压缩、视觉模型识别、API 原始 JSON 和可编辑十列表格。
- 统一页面背景、文字层级、间距、表单边框和按钮状态。
- 确认按钮根据上下文显示“保存识别结果”或“更新识别记录”。
- 打开历史记录时进入现有 `review` 状态，并恢复图片、原始 JSON、产品类型和全部可编辑字段。
- 返回重新识别时退出历史编辑上下文，避免新识别覆盖旧记录。

## 记录栏

记录栏顶部显示标题、记录数量和简短筛选信息，不增加搜索或分类功能。

每条记录显示：

- 产品类型名称。
- 客户。
- 型号/规格。
- 检验日期。
- 最近更新时间。
- 本地记录编号。

点击记录主体进入识别栏并打开可编辑确认页面。每条记录提供删除操作，删除前使用确认弹窗；删除后同步清理对应的本地持久图片。

没有记录时显示空状态和“去识别”操作。

## 本地数据模型

```ts
interface StoredInspectionRecord {
  id: string
  imagePath: string
  rawContent: string
  record: InspectionRecord
  createdAt: number
  updatedAt: number
  syncStatus: 'local'
}
```

本地存储键为 `inspectionHistory:v1`。记录按 `updatedAt` 降序保存，最多保留最近 30 条。

## 图片持久化

拍照或相册返回的是临时文件路径，不能直接用于长期历史记录。首次确认新记录时调用 `wx.getFileSystemManager().saveFile` 保存图片，并把返回的 `savedFilePath` 写入历史记录。

更新已有记录时继续复用原持久图片。删除记录或清理超出 30 条的旧记录时调用 `removeSavedFile` 删除关联图片。图片保存失败时不写入不完整历史记录，并保留当前编辑内容供用户重试。

## 数据操作

新增独立历史仓储模块，负责：

- 读取并校验本地数组。
- 新增记录并生成 `IR-<timestamp>` 编号。
- 按编号更新记录，保留 `createdAt`。
- 删除记录。
- 保持最近 30 条并返回需要删除的旧图片路径。

页面只调用仓储接口，不直接拼接本地存储结构。

## 错误处理

- 本地存储内容损坏时返回空列表，不阻塞识别流程。
- 保存图片失败时提示“无法保存报告图片”，不进入成功状态。
- 写入本地存储失败时保留编辑内容并提示重试。
- 删除文件失败不阻止删除记录，但不向用户显示误导性成功文件状态。
- 打开记录时若本地图片已丢失，仍允许编辑表格，并用缺图占位状态代替预览。

## 测试

- 单元测试历史记录新增、更新、排序、30 条上限和删除结果。
- 单元测试损坏存储回退为空数组。
- 单元测试新记录确认与已有记录更新使用不同路径。
- 运行现有 OCR、压缩、表格归一化和 TypeScript 检查，防止回归。
- 在微信开发者工具中验证悬浮栏安全区、识别中切换、空列表、打开编辑、更新和删除交互。

## 不在本轮范围

- 服务器同步和跨设备历史。
- 搜索、筛选、分页或批量删除。
- 用户登录与权限。
- 历史记录导出。
