# 自然化识别进度条设计

**日期：** 2026-07-24
**范围：** 微信小程序检验报告识别队列的客户端展示进度；不改变上传、识别并发数或后端接口。

## 背景

当前识别卡片共享一条固定的分段进度曲线：6 秒内统一到 92%，实际识别尚未完成时停在 92%，完成后直接变为 100%。多卡同时识别时速度完全相同，且尾段跳变明显。

## 目标

1. 每张识别卡片拥有稳定、可复现但彼此不同的展示节奏。
2. 维持“前段较慢、中后段加快”的总体感受。
3. 6 秒后不固定停在 92%，而是继续以更慢速度向各自的上限推进。
4. 不让模拟进度在真实响应返回前达到 100%；响应返回后立即展示结果，不人为增加等待。
5. 保持每 300ms 刷新、识别队列最多 2 张并发以及现有错误/跳过状态语义。

## 方案选择

采用“**每卡固定进度档案**”方案，而不是每次 tick 随机抖动：

- 建立队列项时，基于条目 ID 派生确定性的伪随机数，生成该卡的进度档案。
- 档案包含：前段速度微差、中段加速度、6 秒目标进度、尾段渐近上限和尾段推进速度。
- 因为档案只生成一次，单张卡片整个识别周期内的运动连续稳定；不同卡片不会呈现相同曲线。

不采用每次刷新都随机的方案，避免进度忽快忽慢。也不采用完成后延迟补齐 100% 的方案，避免人为拖慢已完成识别结果的展示。

## 数据模型

为 `RecognitionQueueItem` 增加一个只读的 `progressProfile`：

- `earlyTarget`：前段节点目标；
- `middleTarget`：中段节点目标；
- `sixSecondTarget`：6 秒时的进度目标；
- `tailCeiling`：真实结果未返回时可逼近但不可达到的上限（95%–98%）；
- `tailRate`：6 秒后逼近上限的速度。

该档案由 ID 的稳定散列生成，测试可通过传入明确档案获得确定预期，不依赖运行时 `Math.random()`。

## 曲线规则

1. **0–约 1.5 秒：** 缓慢推进，体现图片读取、压缩和上传准备。
2. **约 1.5–6 秒：** 按每卡不同斜率加速，避免两张卡同步。
3. **6 秒之后：** 用渐近曲线继续推进，逐渐接近该卡自己的 `tailCeiling`；不固定在一个共同数字。
4. **真实完成：** 立即转为 ready 并置为 100%，不增加伪造延迟。

所有计算保持单调递增，并限制在 0–99%；仅 `ready` 状态使用 100%。

## 验收标准

- 两个不同 ID 创建的队列项，进度档案存在且至少一个关键参数不同。
- 在相同 elapsed 时间下，两张不同 ID 的进度可不同，但同一 ID 重复计算结果一致。
- 6 秒时各卡进度不统一为 92%；超过 6 秒后进度继续增加。
- 超过 6 秒后的任意模拟进度小于 100，且不高于各自 `tailCeiling`。
- 已有队列并发、完成、失败、跳过和重试测试继续通过。
