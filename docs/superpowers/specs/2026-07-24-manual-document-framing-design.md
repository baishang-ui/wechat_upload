# 手动拍摄的检验报告自动框选设计

**日期：** 2026-07-24
**范围：** 微信小程序“拍摄报告”入口的相机采集体验。相册批量导入、识别并发队列、后端 OCR 接口均保持原有行为。

## 背景

当前拍摄入口使用系统媒体选择器，用户无法在拍摄前得到检验报告边缘提示。图片可能带有较大背景、倾斜或透视变形，降低后续识别稳定性。

## 目标

1. 提供应用内相机预览，实时提示检验报告的可拍摄范围。
2. 自动检测单据四边并显示框线，但始终由用户主动点击快门。
3. 拍摄后优先按检测出的文档边界裁切单据，再沿用现有图片压缩、双并发识别和人工审核流程。
4. 边缘检测不可用、无法稳定识别或裁切失败时，允许用户继续以原图拍摄，不阻断识别。

## 交互设计

### 入口

“拍摄报告”进入专用相机采集页；“从相册批量添加”维持不变。

### 预览状态

- **未检测到单据：** 显示中性色取景框和提示“请将检验报告放入取景框”。
- **检测中或边缘不稳定：** 显示浅色跟随框和提示“正在定位单据边缘”。
- **检测稳定：** 显示绿色四边形框和提示“已识别文档边缘，可拍摄”。
- **降级状态：** 检测服务不可用时，保留相机、快门和“直接拍摄”提示。

### 拍摄与确认

用户点击快门后：

1. 若边缘结果连续稳定，执行文档区域裁切；
2. 显示拍摄结果预览，提供“重拍”和“使用照片”；
3. 用户确认“使用照片”后，将最终图片加入现有识别队列；
4. 若裁切处理失败，则提示已保留原图，仍可“使用照片”。

不会基于“稳定一段时间”自动触发拍照。

## 技术设计

### 新页面与数据流

新增独立的文档相机页面，以相机预览作为图像来源；页面返回最终临时图片路径。首页的 `takePhoto` 仅负责打开采集页，接收到确认后的路径后调用既有 `enqueueRecognitionFiles`。

### 实时边缘检测

通过低频抽帧执行单据候选四边形检测，并将结果平滑为 UI 框线。检测输出包含：

- 是否检测到四边形；
- 四个角点的归一化坐标；
- 置信度；
- 最近连续帧是否稳定。

为了控制预览负载，检测帧率与渲染帧率分离；只在结果显著变化时更新页面状态。稳定判定基于连续帧角点位置与面积变化阈值。

### 拍后图像处理

拍摄图像使用与实时检测相同的归一化边界坐标换算为原图坐标。第一版检测器输出轴对齐矩形，因此处理流程为：裁切候选区域、限制输出尺寸和质量、输出临时 JPEG。若任一步失败，回退为相机原图。四角数据结构会保留，后续可在引入透视检测和校正后升级为透视拉正。

### 降级与权限

- 相机权限拒绝：展示明确说明并允许返回首页。
- 无边缘检测结果：快门保持可用，拍摄后直接使用原图。
- 裁切失败：不丢弃照片，回退原图并提示。
- 仅在用户确认“使用照片”后才加入识别队列。

## 测试策略

1. 纯函数测试：四边形稳定判定、归一化坐标到图片坐标转换、检测结果降级判断。
2. 页面行为测试：稳定结果切换为“可拍摄”、检测失败时快门仍可用、确认后仅传递最终图片路径。
3. 现有队列回归：相机页确认的图片继续走压缩与最多两张并发识别。

## 验收标准

- 用户能从“拍摄报告”进入相机采集页。
- 在检测到完整且稳定的单据时，预览显示绿色框线。
- 用户必须手动点击快门；系统不会自动拍摄。
- 检测不到边缘时，用户仍可拍摄并进入识别队列。
- 连续稳定检测到文档时，确认使用的图片为自动裁切后的图片；裁切失败时使用原图。
- 相册批量导入和既有识别队列功能不回归。
